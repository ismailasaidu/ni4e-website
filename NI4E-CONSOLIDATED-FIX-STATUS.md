# NI4E consolidated fix pass — 20 October 2026

## Scope of this package
This package consolidates the latest available NI4E source, rather than introducing another patch-only archive. It includes the current membership status card, portal routes and sections, admin payment reporting, and the event-payment migration that were present in the latest source archive.

## Concrete source change in this pass
- Fixed the signed-in account menu JSX grouping in `src/components/Header.jsx`, so the member portal/profile/payment-history actions are conditionally grouped for non-admin users rather than malformed as adjacent conditional JSX.

## Payment flow notes
- `supabase/functions/verify-membership-payment/index.ts` verifies Paystack server-side and treats demo certificate creation as optional. A missing optional certificate table should not convert a confirmed charge into a checkout failure.
- If Paystack verification succeeds but a later membership synchronization operation fails, the function returns HTTP 200 with `verified: true`, `syncPending: true`, and explicit instructions not to pay again. This prevents a generic non-2xx response from being mistaken for a failed charge; it does not itself guarantee that every membership row synchronized successfully.
- Never repeat payment to test this existing transaction.

## Portal and status experience in source
- Main navigation includes Member Portal (`/member/dashboard`).
- Separate portal routes exist for profile, membership details, payment history, events, and resources/documents.
- The membership status page displays the premium member details card and an Open Membership Portal action when the membership is active and a successful payment is linked.
- Official membership numbers are not generated by this package. Admin assigns the approved number under Admin → Members.

## Event-payment migration
`supabase-stage-3-integrated-event-payments.sql` is included. It creates/reconciles `public.event_payments` and applies admin read access. It assumes `public.event_registrations` and `public.is_ni4e_admin()` already exist. Review those prerequisites in the target Supabase project before running it. Do not run the entire base schema as a shortcut. This package does not execute SQL against the live database.
