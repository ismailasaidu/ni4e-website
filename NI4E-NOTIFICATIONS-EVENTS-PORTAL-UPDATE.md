# NI4E Member Portal update — notifications and event interaction

## Included in this pass
- Added a bell dropdown with unread count, saved notification history, mark-all-read, mark-single-read, and Supabase Realtime subscription for new notifications.
- Added `supabase/migrations/20261020_member_notifications.sql` to create the private notification table and database triggers for application submissions/reviews, membership number/status/validity updates, membership payment changes, and event registration changes.
- Restricted notification reads and read-state updates to the signed-in member. Members can only update `read_at`; inserts are generated by trusted database triggers.
- Removed the Messages link from the member More menu. Application history remains in the application tracker.
- Made the official membership number a prominent identity block on the member dashboard.
- Added an Applications shortcut to the dashboard quick links.
- Made the demo event registration action clickable so it explains why demo content cannot be booked instead of appearing to do nothing. Real event registration still validates sign-in, event registration status and payment setup.
- Added optional agenda display to event details when the event metadata includes an `agenda` field.

## Required Supabase setup
Run `supabase/migrations/20261020_member_notifications.sql` in the Supabase SQL Editor before testing the notification bell. The bell intentionally displays a setup warning until the table exists.
